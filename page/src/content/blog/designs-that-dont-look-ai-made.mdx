Ask any coding agent for "a modern landing page" and you can predict the result before it renders: a purple-to-blue gradient, a centered headline, three feature cards with an emoji each, pill buttons, soft shadows, and a testimonial carousel nobody asked for.

The model isn't lacking taste. It's averaging. With no constraints, it falls back to the most common patterns in its training data — which today means default Tailwind and shadcn/ui. The fix isn't a better adjective in the prompt ("clean", "minimal", "premium" all land on the same median). The fix is a design system the model has to follow.

And a design system is much more than colors and fonts.

## The Tells

Most of what makes a page read as AI-made isn't the palette. Look for these:

- **Color:** indigo/violet accents, gradients on text and buttons, every gray slightly blue.
- **Shape:** the same `rounded-xl` on everything, pill buttons, cards nested in cards, a shadow on every surface.
- **Buttons:** two big pills side by side ("Get started" + "Learn more"), an arrow icon tacked on, identical weight for primary and secondary actions.
- **Layout:** everything centered, everything in a card, uniform 3-column grids, generous but meaningless whitespace, one section per idea in the same rhythm all the way down.
- **Type:** one sans-serif at three sizes, bold headlines with no hierarchy below them.
- **Decoration:** glassmorphism, blurred blobs in the background, gradient borders, an icon on every heading.
- **Copy:** "Unlock the power of…", "Seamless", "Supercharge your workflow", emoji bullets.
- **Motion:** everything fades up on scroll, at the same speed.

None of these is wrong on its own. Together, unchosen, they're a fingerprint.

## What a Design System Actually Covers

To get something distinct, specify each layer — the model fills any layer you skip with the defaults above.

**1. Tokens.** Colors (with roles: background, surface, text, muted, border, accent), type scale, spacing scale, radius, elevation. Few and named. "Accent is `#B4532A`, used only for links and hover" beats a 12-step palette the model will spread everywhere.

**2. Shape language.** One decision that propagates: are corners square, slightly rounded, or round? Is structure made of borders, shadows, or background shifts? Pick one per question. A square-cornered, border-only system already looks unlike 90% of generated UIs.

**3. Components.** Buttons are where personality shows. Define:
- Hierarchy: what a primary, secondary, and tertiary action look like — and that there is only one primary per view.
- Shape and size: height, padding, radius, whether text is uppercase.
- States: hover, focus, active, disabled, loading.
- What's *not* a button: inline actions as text links, destructive actions behind a confirmation.

Do the same for inputs, cards (or the decision not to use them), tables, and navigation.

**4. Layout patterns.** How a page is built: grid columns, max widths, alignment (left-aligned is a strong signal of intent), density, how sections are separated. Name the patterns you want ("dense table over card grid", "sidebar + content, not centered hero") and the ones you don't.

**5. Voice.** Copy is part of the design. Short, specific, no marketing verbs. Give two or three example sentences in your voice.

**6. Motion.** Either a short list of allowed transitions with durations, or "no animation except hover color".

## DESIGN.md: The Spec Claude Reads

The convention for putting all of this in one place is a `DESIGN.md` at the repo root: tokens, shape language, component rules, layout patterns, voice, and a do/don't list, in Markdown.

You don't have to write it from scratch. Catalogs like [designmd.co](https://www.designmd.co/catalog), [ui-skills.com](https://www.ui-skills.com/design-md), and [shadcn.io/design](https://www.shadcn.io/design) publish ready-made ones that capture the design language of well-known products. They're the fastest way to get a coherent system instead of a pile of preferences.

A skeleton, if you write your own:

```markdown
# Design

## Principles
Dense, quiet, editorial. Structure from lines, not boxes.

## Tokens
- Background #FBF8F3 · Text #201B15 · Muted #72614A · Border #E7D9C4
- Accent #B4532A — links and hover only, never fills
- Type: Fraunces for headlines, Inter for body, JetBrains Mono for labels
- Spacing: 4px base; sections 96px apart

## Shape
- Square corners everywhere. No shadows. 1px borders for structure.

## Components
- Button, primary: solid text color, square, 40px tall, mono uppercase label.
  One per view.
- Button, secondary: 1px border, transparent.
- Links: accent color, underline on hover.
- Cards: avoid. Use a grid with 1px gaps instead.

## Layout
- Left-aligned. Max width 72rem. 12-column grid.
- Lists and tables over card grids.

## Voice
Plain and specific. "Builds in 3 seconds", not "Blazing-fast performance".

## Don't
- Gradients, glassmorphism, background blobs
- rounded-*, shadow-*
- Emoji in UI, icons on every heading
- Centered hero + 3 feature cards
```

## The Workflow

1. **Pick a reference.** Start from a catalog entry whose feel fits, or from a product you admire. Screenshots help too — Claude reads images.
2. **Make it yours.** Change the accent, the fonts, and at least one structural decision. A borrowed system is a starting point; the logo, name, illustrations, and copy stay the original brand's.
3. **Wire it in.** One line in `CLAUDE.md` (or `AGENTS.md`): "All UI follows `DESIGN.md`. Use only its tokens; if something isn't covered, ask instead of inventing."
4. **Build the parts before the pages.** Have Claude make a single components page — buttons in every state, inputs, a table, nav — and fix that first. Pages assembled from approved parts inherit the system.
5. **Review visually.** Have Claude screenshot the result (Playwright or the browser tools) and critique it against `DESIGN.md`, item by item. Drift shows up in screenshots long before it shows up in code review.
6. **Update the spec, not the page.** When you correct something twice, it belongs in `DESIGN.md`.

## Prompting Tips

- **Constraints beat adjectives.** "Square corners, no shadows, one accent" produces a look; "make it elegant" produces the median.
- **Write the don'ts.** The defaults are strong, so name them explicitly.
- **Ask for options.** "Three different layouts for this page, each with a one-line rationale" gets you out of the first, most average answer.
- **Name the trade-off.** "Optimize for scanning 50 rows" leads to a different interface than "optimize for first impression".

## A Real Example

This site does it with one paragraph in `CLAUDE.md`: warm paper palette, a single terracotta accent, Fraunces headlines, mono uppercase labels, structure from 1px hairlines, never `rounded-*` or `shadow-*`, card grids built as `gap-px` grids so the background shows through as lines. That paragraph is the whole design system, and it's enough to keep every new page consistent — including this one.
